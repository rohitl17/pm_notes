# Product Engineering Copilot

A modular Streamlit console that pairs product, architecture, and research workflows into one AI-augmented experience. The Copilot brings together backlog triage, requirements mining, blueprint authoring, market scanning, readiness scoring, and red-team reviews so distributed product/engineering leaders can move from idea to execution faster.

## Vision & product philosophy
- **Single pane for product & engineering:** PMs, architects, and staff engineers often bounce between spreadsheets, docs, and meeting notes. The Copilot centralizes decisions, drafts, and external signals to keep everyone aligned.
- **Human-in-the-loop AI:** Every module keeps ownership with the user. LLMs provide structured drafts, critiques, or research notes but the UI surfaces intermediate data (matching rows, research feeds, scoring tables) so humans validate before sharing.
- **Plug-and-play foundation:** The project uses a deliberate modular design so organizations can swap components (LLM provider, sourcing API, identity provider) without rewriting the UI.
- **Transparency by default:** Each recommendation or critique references the source (knowledge base excerpts, uploaded docs, curated feeds) making it audit-friendly.

## Experience map
| Module | Users | Problem solved | Key outputs |
| --- | --- | --- | --- |
| Login & home | Admins, PMs | Gate access, orient to capabilities | Navigation, usage notes |
| Design Q&A | Staff engineers, architects | Need answers grounded in prior decisions | Single-response Q&A or spreadsheet batch responses referencing knowledge base rows |
| Requirements Miner | PMs, TPMs | Turn PRDs/RFCs into structured requirements | Markdown tables (Requirement, Capability, Acceptance Criteria, Open Questions) |
| Pattern Workshop | Architects, SRE | Co-build reusable blueprints with context | Chat-based blueprint iterations sourced from reference docs |
| Tech Radar | Product strategy, partnerships | Track external opportunities/sourcing signals | Curated + live web signals with research briefs |
| Readiness Scoring | Product councils | Decide go/hold based on multi-factor inputs | Weighted readiness %, advisory notes |
| Architecture Red-Team | Principal engineers | Stress-test drafts pre-review | Full critique with severity table & checklist |

## Design & engineering decisions
1. **Streamlit** was chosen for rapid prototyping, excellent layout primitives, and zero-config deployment. Sidebar navigation mimics console applications and keeps modules discoverable.
2. **Stateful sections** such as `pattern_chat` use `st.session_state` for conversational continuity while other modules remain stateless for simplicity.
3. **Pluggable data sources**: `kb_sample.csv` demonstrates the knowledge base ingestion. `MOCK_SIGNAL_FEED` powers radar demos; switching to SerpAPI or internal feeds just requires populating `st.secrets`.
4. **LLM abstraction**: `call_llm()` centralizes OpenAI usage and provides mock responses when no API key exists, keeping the UI testable offline.
5. **Optional dependencies**: Word parsing (`python-docx`) and HTTP (`requests`) are optional; the UI informs the user when a feature is unavailable rather than crashing.
6. **Authentication placeholder**: `authenticate()` is intentionally simple (demo credentials) and highlighted as a swap-out for SSO.

## Feature deep dive
### 1. Design Q&A
- Upload a knowledge base (CSV/XLSX) and filter by tags.
- The copilot surfaces matching rows before generating an answer so users can cite assets confidently.
- Batch mode adds a response column to backlog spreadsheets and downloads them with LLM-generated design notes.

### 2. Requirements Miner
- Accepts `.docx` uploads or pasted text.
- Prompts the LLM to output a markdown table with Requirement, Capability Group, Acceptance Criteria, and Open Questions fields.
- Custom instructions let teams shape the extraction rubric for different document styles.

### 3. Pattern Workshop
- Multi-file uploader (text or Word) for reference material.
- Maintains a chat transcript so architects iterate on diagrams, runbooks, or template sections.
- Base instructions define the target blueprint; subsequent prompts (via chat input) drive revisions.

### 4. Tech Radar
- Mixes curated signals (`MOCK_SIGNAL_FEED`) with live Google/SerpAPI scraping (optional).
- Filters by keywords, geography, sector, budget, and due date.
- Each signal can trigger an on-demand research brief generated by the LLM.
- "Summarize signal landscape" aggregates themes for leadership updates.

### 5. Readiness Scoring
- Captures initiative context, priorities, and self-assessed scores across architecture fit, innovation, compliance, team readiness, and delivery risk.
- Weighted calculation returns a readiness percentage plus go/hold recommendation.
- Generates an advisory narrative describing gaps and next steps.

### 6. Architecture Red-Team
- Upload/paste a draft, choose focus areas, and select tone (Balanced → Brutal).
- LLM returns summary judgement, severity-ranked findings, annotations, and required experiments.
- Useful ahead of formal governance reviews to catch blind spots early.

## Sample knowledge base
`kb_sample.csv` contains representative rows (component descriptions, version notes) so Design Q&A can run without a corporate data export. Replace it with your internal catalog for production use.

## Setup
1. **Install**
   ```bash
   pip install streamlit pandas openai python-docx requests
   ```
2. **Secrets (optional but recommended)**
   - `OPENAI_API_KEY` for real LLM answers.
   - `SERPAPI_API_KEY` for live Tech Radar sourcing.
   Place them in `.streamlit/secrets.toml` or environment variables.
3. **Run**
   ```bash
   streamlit run app.py
   ```
4. **Log in** with the demo users (`demo/copilot-demo` or `architect/welcome123`). Swap the `authenticate` function for your identity provider before real use.

## Extensibility roadmap
- **Identity:** Hook into Okta or Azure AD for SSO and auditing.
- **Knowledge base connectors:** Replace CSV uploads with search APIs (Confluence, Notion, internal registries).
- **Workflow outputs:** Push recommendations into Jira, ADO, or PRD docs automatically.
- **Analytics:** Track module usage and response quality to prioritize future investments.
- **Model provider options:** Add adapters for Azure OpenAI, Anthropic, or on-prem LLMs to meet enterprise requirements.
